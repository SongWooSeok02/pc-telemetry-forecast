# S1-07 검증 결과와 남은 조건

작업 상태: **부분 구현·검증 중, Done 아님**. [기계 판독 실행 기록](s1-07-local-validation.json)은
익명 개발 PC의 OS/런타임, 기반 커밋·변경 파일 SHA-256, 재현 명령, 기대/실제 결과,
UTC 실행 시각과 성공/실패를 담는다. 기반 커밋 위 미커밋 변경을 검사했으므로 파일 해시를
함께 비교한다. 실제 센서값·실제 토큰·로컬 DB·모델은 제출하지 않았다.
로컬 Node는 24.16.0이며 CI의 Node 22 결과는 별도로 확인한다.

| 검증 | 기대값 | 실제 결과 |
|---|---|---|
| Python 컴파일 / Ruff 치명 오류 / JS 구문 | 종료 0 | 통과 |
| 기존 증거 실행기 회귀 | 2개 성공 | 통과 |
| 파티션 작업자 | 성공 시 commit/로그, 실패 시 종료 1·접속 정보 미노출 | 모의 검사 2개 통과 |
| 계약 생산자·HTTP/트랜잭션·시각 상태 | 33개 성공 | 통과 (센서 실측 아님) |
| YAML 구문 / 공백 | 파싱 성공 / 종료 0 | 통과 (Compose 의미 검증 아님) |
| 의도적 Python 문법 오류 / 복구 | 컴파일 종료 1 / 0 | 로컬에서 기대대로 검출·복구 |
| Compose 이미지·빈 DB·API health·파티션 작업자 | 빌드/마이그레이션/작업자 0, HTTP 200 | 미실행: Docker 없음 |
| 새 팀원 환경 재현 | 문서 순서대로 실행 성공 | 미실행 |
| 원격 PR CI의 실패/복구 | 실패 run과 복구 run 링크 | 미실행, 로컬 실패 검출로 대체하지 않음 |
| 실제 PostgreSQL 통합 검사 | backend CI 성공 artifact | S1-07에서는 재실행 안 함, 기존 S1-03 결과와 구분 |
| 에이전트·UI·예측 작업자 빌드 | 해당 코드의 빌드·정적·핵심 검사 | 소스 부재로 미연결 |
| PC 2대 지원·드라이버·권한 | 실제 관측 증거 일치 | [지원 표](sensor-support.md) 미검증 |
| 다른 팀원 1명 리뷰·필수 검사 설정 | 승인 및 PR checks | 대기 |

개발용 API/DB/파티션 관리 작업자는 [실행 안내](../infra/README.md)를 따른다.
파티션 작업자의 예외 로그가 접속 오류 원문을 노출할 수 있어 오류 클래스·SQLSTATE만
남기도록 바꿨으며, 합성 민감 문자열이 로그에 나오지 않는 회귀 검사를 추가했다.
로그만으로 세부 접속 오류를 확인하기 어려운 경우 비밀을 공유하지 않고 운영자가 현장에서
연결 설정을 점검한다.

차단/후속 담당과 다음 확인:

- B: Docker 가능한 새 환경에서 Compose 검증, PR의 전체 CI 및 의도적 실패/복구 확인,
  검사 필수화 여부·팀원 리뷰 확인. 다음 확인은 2026-11-03 KST 마감 전.
- A: S1-02a의 PC 2대 관측 및 정확한 센서/드라이버·권한 결과 제공, 에이전트 프로젝트
  제공 시 Windows 빌드·정적·핵심 테스트 연결. 다음 확인은 같은 마감 전.
- C: 대시보드·예측 작업자 구현과 실행 전제 제공, 해당 PR에서 CI 확장. 구현 제공 시 확인.

자체 리뷰에서 비밀번호를 URI에 직접 삽입하면 특수문자 때문에 접속이 실패할 수 있는
문제를 수정했다. Compose는 빈 DSN과 libpq의 PG* 환경변수를 사용한다. 또한 CI 공백
검사를 현재 커밋 검사로 바꿔 checkout 이후 빈 작업 트리만 검사하는 문제를 보완했다.
현재 소스에서 추가 병합 차단 결함은 발견하지 못했으며, 실제 Docker 실행 결과는
PR CI에서 확인해야 한다. 이 자체 리뷰는 다른 팀원의 승인을 대신하지 않는다.

기존 `docs/discord-project-overview*` 파일은 이번 작업 산출물에 포함하지 않는다.
