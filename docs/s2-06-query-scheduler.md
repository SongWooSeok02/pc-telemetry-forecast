# S2-06 React/TypeScript 공통 조회 스케줄러

## 동작 계약

- `performance.now()` 기반 단조 시간과 공통 타이머 하나를 사용합니다. 현재값과 과거 차트는 등록된 작업으로 같은 스케줄러를 공유하며, HTTP 요청은 한 번에 하나만 진행합니다.
- 작업 등록/PC·센서·기간 변경은 새 조건으로 한 번 조회합니다. 같은 키의 이전 요청은 `AbortController`로 취소하고, 응답 코드에서도 취소된 결과를 반영하지 않습니다.
- 자동 주기는 이전 요청 시작 시각에 선택 간격을 더해 정합니다. 요청이 간격보다 오래 걸리면 지난 주기 수만큼 요청을 쌓지 않고, 완료 후 최대 한 번만 실행합니다.
- 자동 주기 변경은 기존 예약을 재설정하고 바로 조회합니다. 현재 실행 중인 동일 작업은 중복 호출하지 않으며 다음 예약은 현재 요청 시작 시각 기준 새 주기를 따릅니다.
- 수동 모드에서는 정기 예약을 제거합니다. 최초 작업 등록·PC/조회 조건 변경은 조회하고, `지금 갱신`은 실행 중 작업과 중복시키지 않습니다. 실패 후 자동 재시도/지수 대기는 S3-08에서 확장할 범위입니다.
- 브라우저 문서가 숨겨지거나 WebView 호스트가 최소화 상태를 보내면 타이머를 제거하고 실행 중 요청을 취소합니다. 자동 모드에서 다시 보이면 즉시 새로 조회합니다. 수동 모드 복귀는 새 요청을 발생시키지 않습니다.
- 작업 해제와 앱 루트 정리는 등록 취소, 요청 중단, 타이머 정리를 수행합니다. 수집·전송·예측 주기는 변경하지 않습니다.

## WebView2 메시지

브라우저 문서 가시성과 .NET 호스트 가시성을 AND로 결합합니다. WebView2 호스트는 최초 화면 준비 시점과 최소화/복원 때 다음 JSON 메시지를 `CoreWebView2.PostWebMessageAsJson`으로 보냅니다.

```json
{"type":"pc-telemetry:host-visibility","visible":false}
```

`visible`은 실제 표시 상태입니다. 예를 들어 컨트롤러의 `IsVisible` 값을 변경한 뒤 동일한 상태를 메시지로 전달합니다. 웹에서는 `window.chrome.webview` 메시지 이벤트를 받아 상태를 갱신합니다. 이 PR 브랜치의 호스트 발신자 연결 및 패키지 앱 통합 시연은 후속 협업 항목입니다. 최신 통합 검증 범위는 아래 2차 리뷰 기록을 따릅니다.

- 재현: `node --experimental-strip-types --test dashboard/tests/queryScheduler.test.ts`

- 타입 검사: `node node_modules/typescript/bin/tsc -b` 통과
- 프로덕션 빌드: `node node_modules/vite/bin/vite.js build` 통과 (Vite 6.4.5)
- 실제 .NET 최소화/복원은 호스트 프로젝트 부재로 검증하지 못했습니다. 서버 읽기 API 미구현으로 실제 telemetry 요청 통합도 S2-05/S3-03 의존성에 남습니다.

## 완료 조건과 2차 리뷰 수정

C는 React/TS 공통 스케줄러와 웹·호스트 가시성 상태 결합을 담당하고, A는 .NET 최소화/복원 이벤트 및 IsVisible 상태 전달을 담당합니다. 단조 시간 예약·주기 변경·느린 요청·수동 모드에서 타이머/요청 중복과 밀린 요청 누적을 방지합니다. 숨김은 자동 조회를 중단하고 자동 모드 복귀는 즉시 조회하며, 수동 모드는 복귀·실패 후 자동 요청을 하지 않습니다.

현재값/과거 조회에 공통 활동 상태 정리를 적용했습니다. 요청을 시작할 때 직전 표시 상태를 보관하고 취소 신호를 받으면 HTTP 종료를 기다리지 않고 즉시 복원합니다. 현재값의 ready/error/unavailable/idle 상태와 과거 차트의 busy 및 이전 오류를 복원하며 기존 데이터는 유지합니다. 취소 후 늦게 끝나는 작업은 새 요청의 조회 중 상태를 해제하지 않습니다. 정상 응답·실패 시 활동 상태도 정리합니다.

검증 기록(2026-11-19 KST): Windows x64, Node.js v26.13.0, dashboard v0.1.0, 수정 기준 커밋 8b7c7b0 이후. npm run test:scheduler 15개 통과, npm run build(TypeScript/Vite 6.4.5) 통과, git diff --check 통과. 재현: 수동 조회 시작 → 웹 숨김 또는 WebView 호스트 visible:false → visible:true → 취소된 응답 종료. 기대/실제: 즉시 이전 상태 복원, 기존 데이터 유지, 복원 후 요청 수 1회 유지, 명시 갱신 후 2회. 실패 후 60초에도 자동 재시도와 타이머 0개 확인. 취소된 이전 요청 종료가 후속 조회 중 상태를 해제하지 않는 검사도 통과했습니다.

이 검증은 가짜 타이머·문서/호스트 이벤트와 실제 공통 활동 상태 함수의 통합 검사입니다. React 화면 렌더링 및 실제 Windows WebView2 최소화/복원 시연은 수행하지 않았습니다. origin/main에는 별도 호스트 프로젝트가 추가되어 있으나 이 PR 브랜치에는 아직 포함되지 않았습니다. A의 발신자 연결과 실제 웹·앱 통합 검증이 남아 있으므로 전체 완료로 표시하지 않습니다.
