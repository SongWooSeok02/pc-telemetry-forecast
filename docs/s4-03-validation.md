# S4-03 가상 10 PC 저장·조회·보존 검증

## 범위와 합격 기준

- PC 10대 × 센서 12개 × 초당 1회 × 86,400초 × 7일 = **72,576,000 원시 행**이다. 하루 10,368,000행이며 지속 수집 목표는 초당 120행이다. 전송 배치와 별개로 센서값 하나당 한 행을 저장한다.
- 3초는 README의 최소 조회 **주기**다. 이 시험에서는 10개 클라이언트의 동시 조회가 다음 주기 전에 완료되고 각 응답이 기대 포인트 수와 일치해야 한다.
- 수신 시각 경계가 168시간을 넘은 UTC 일별 파티션만 제거 대상이다. 집계 대기 원시 데이터는 파티션 제거 함수가 보존해야 한다. 집계 완료와 조회 잠금 해제 후 동일 파티션을 제거하고 다음 날짜 파티션을 확인한다.

## 재현

1. S3-03 집계·S4-02 운영 마이그레이션을 포함한 이 PR의 체크아웃에서 PostgreSQL 16+와 Python 3.12, [백엔드 의존성](../backend/requirements.txt)을 준비한다.
2. 별도 PostgreSQL 인스턴스에 빈 `s403_bench_full` 데이터베이스를 생성한다. 데이터 디렉터리, WAL, 임시 파일용 여유 공간을 확보한다. 시작 시 public 스키마가 비어 있어야 한다. 검증 계정은 마이그레이션·파티션 DDL을 실행할 수 있어야 한다. 운영 서버와 공유하는 인스턴스에서 실행하면 부하가 전파될 수 있다.
3. 로컬 비밀 환경 변수로 `S403_DSN`을 주입한다. 저장소 루트에서 실행한다. stdout은 JSON Lines 형식이고 시각은 UTC다. 축소 검증은 새 빈 `s403_bench_*` DB에서 `--smoke`를 지정한다.

```bash
python -m pip install -r backend/requirements.txt
PYTHONPATH=. python tests/run_s4_03.py > s4-03-full.jsonl
```

4. `result=pass`와 종료 코드 0을 확인한다. `plan`에는 원시 1분·6시간과 7일 범위의 1분 집계 쿼리의 EXPLAIN ANALYZE 및 버퍼가 포함된다. `poll_cycle`에는 실시간 3초 간격으로 제출한 10개 요청의 개별 시간과 전체 사이클 시간이 있다. 각 클라이언트는 같은 소유자의 서로 다른 PC를 조회한다. 첫 주기는 원시 60포인트를, 이후 주기는 동결한 가상 시계에서 증분 커서의 0포인트를 검증한다.
5. 집계 두 해상도는 알려진 합성 값에서 미리 만들고, 만료 후보의 1분 버킷 1개를 큐에 넣어 실제 작업자가 재계산한다. `prune_pending` 후 파티션 유지 및 집계 평균 31.5, 최댓값 61, 유효 60건을 확인한다. 두 번째 세션이 원시 테이블 읽기 트랜잭션을 유지하면 5초 뒤 SQLSTATE `55P03`을 기대한다. 해제 후 운영과 동일한 `prune_telemetry`로 재시도한다. 이 함수는 연결된 테이블을 직접 DROP한다. 측정은 원시 파티션 정리 호출에 한정하며, 운영에서 같은 트랜잭션에 들어가는 `prune_telemetry_metadata` 비용은 별도다.

p95는 개별 요청 100개를 정렬하여 95번째 값을 사용했다. 계획의 공유 버퍼는 블록 수다. 조회는 적재 직후 같은 호스트에서 실행한 FastAPI TestClient 기준이다. 10개 요청은 동일 소유자 잠금을 공유했고, 냉시작·외부 네트워크·브라우저 렌더링·동시 지속 쓰기는 범위 밖이다. 1분 및 6시간 원시 쿼리는 수신일 기준 보존 경계와 별도로 관측 시간으로 필터링하므로 실행 계획에서 실제 파티션 접근과 읽기 블록을 확인한다.

적재 시 WAL LSN이 26.89 GiB 증가했다. 이 수치는 클러스터 전체 생성량이다. 같은 인스턴스의 별도 소형 DB에서 회귀를 함께 실행했으므로 그 WAL도 소량 포함되며, 디스크에 동시에 보존된 WAL 점유량은 별도로 산정해야 한다. 적재 도중 약 11~13초 간격의 요청 체크포인트 경고를 관찰했다. 운영 일괄 적재에서 같은 경고가 재현되면 `max_wal_size`를 늘린 비교 시험에서 처리량과 WAL 여유를 함께 측정한다. 실제 수신 지연과 인덱스 키 길이, 원장, 큐, 백업, 롤업의 30일·90일 보존을 포함하면 운영 용량이 증가한다. 자정 경계에 걸친 부분 보존일까지 감안해 원시 공간은 8일치도 수용할 수 있어야 한다.

전체 적재와 조회는 위 앱·스키마에서 먼저 시작했다. 축소 자체 리뷰에서 변경 없는 커서 조회에 센서 메타데이터가 필요하다는 점을 확인하여, 전체 시험의 조회 시작 전에 동일한 합성 메타데이터 10건을 별도 세션으로 입력했다. 현재 러너는 이를 자동으로 입력한다. 위 로그의 shared_buffers 원시값은 `16384` × `8kB`가 붙어 표시된 것으로, 현재 러너는 사람이 읽을 수 있는 단위로 출력한다. 계획 행 수 검증과 운영 정리의 30초 문장 제한을 추가한 최종 러너는 축소 시험에서 재검증했다.
