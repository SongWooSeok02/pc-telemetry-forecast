# S3-08 조회 복구·응답 버전·차트 상태

작업 카드: [#40](https://github.com/SongWooSeok02/pc-telemetry-forecast/issues/40). #39 위에 쌓는 후속 구현입니다. 현재값·과거 차트·예측 비교를 같은 스케줄러의 단일 실행 슬롯으로 관리합니다.

## 재시도 계약

- 선택 주기는 3·5·10·30초·수동입니다. `performance.now()` 단조 시간으로 예약하며 자동 실패 n회 후 간격은 `min(60초, 선택 주기 × 2^(n-1))`입니다. 5초 선택 시 5→10→20→40→60→60초입니다.
- 재시도 시한은 실패가 끝난 시각부터 계산합니다. 느린 요청이 실패한 직후 밀린 주기를 연속 실행하지 않습니다. 성공하면 실패 횟수와 재시도 시한을 초기화하고 S2-06의 이전 요청 시작 기준 정상 주기로 복귀합니다.
- 현재값·과거 차트·예측 비교가 실패 여부를 스케줄러에 전달합니다. 네트워크 오류, HTTP 408/429/5xx는 재시도 대상이며 서버가 `retryable:false`로 반환하면 자동 재시도를 중단합니다. 401/403/404/422와 형식·PC·센서·단위 오류는 자동 재시도하지 않습니다. 서버 플래그가 인증 오류를 재시도 가능하게 바꾸지 못합니다.
- 수동 모드에는 정기 조회·자동 재시도가 없습니다. 수동 전환은 예약과 대기 중 자동 실행 사유를 제거합니다. 숨김 중 자동 주기 변경으로 대기한 요청도 이후 수동 전환 시 제거해 복원 때 자동 실행되지 않게 합니다.
- `지금 갱신`은 재시도 대기/영구 오류 중에도 명시적으로 한 번 다시 시도합니다. 진행 요청이 있으면 후속 한 번으로 합칩니다. 권한 거부로 해당 PC 작업이 해제된 경우 같은 버튼으로 선택 PC를 다시 확인합니다.
- 재시도 대기 중 자동 주기를 바꾸면 새 주기와 실패 횟수로 변경 시점부터 대기를 다시 계산합니다. 수동→자동, 숨김→자동 복귀는 S2-06대로 즉시 한 번 조회합니다. 반복 실패 횟수는 성공 전까지 유지합니다.

## 상태와 경합

일시 조회 오류에는 마지막 성공 값과 오류를 유지합니다. 재조회 시작으로 이전 오류를 지우지 않으며 성공 응답 후에 지웁니다. 마지막 관측·수신·화면 갱신 시각과 데이터 경과를 함께 표시합니다. 예측 비교도 마지막 원시 관측의 경과 시간을 표시합니다. 재시도 알림은 실패 작업·대기 간격·자동 중단 여부를 표시하며 초 단위 카운트다운이 아니라 **해당 상태 갱신 시점 기준** 대기입니다. 별도 조회 타이머는 만들지 않습니다.

PC·센서·단위·기간/세션 범위에 응답 버전을 부여하고, 렌더 시 범위 변경부터 이전 응답을 거부합니다. A→B→A로 돌아와도 첫 A 응답은 새 A에 반영하지 않습니다. 요청 등록 키의 이전 버전 콜백을 새 범위로 실행하지 않으며 `AbortSignal`과 버전을 모두 확인합니다. 이전 요청의 성공/실패는 새 작업의 재시도 횟수에 반영하지 않습니다.

PC를 바꾸면 이전 PC 센서값을 현재 PC 값으로 표시하지 않습니다. 과거 차트 캐시에 단위를 포함해 단위 변경 시 재사용하지 않습니다. 차트 컴포넌트를 key로 재생성하지 않으므로 조회 실패·성공·자동/수동 전환과 PC/대상/기간 변경에서 상대 줌 상태를 유지합니다. 과거 차트의 기간 선택도 줌을 강제로 초기화하지 않습니다. 페이지 새로고침·scrollTo는 사용하지 않으며 전체 범위 버튼만 줌을 초기화합니다.

숨김은 웹 문서 가시성과 WebView2 호스트 가시성을 AND로 판단합니다. 숨기면 타이머를 제거하고 진행 요청을 취소합니다. 종료 시 가시성 바인딩과 모든 작업 등록을 해제하고 요청/예약을 정리합니다. 취소된 요청은 실패로 세지 않으며 취소 전 표시 상태를 복원합니다. 실제 fetch가 취소를 무시하고 늦게 끝나면 슬롯을 그때까지 점유하되 이전 결과는 버립니다. 이전 HTTP가 끝나기 전에 새 HTTP를 병렬 실행하지 않습니다.

## S3-07 인증 연동

`origin/codex/s3-07`의 `e7cebae`에서 `BrowserSession`, `SessionGate`, 해당 경계 검사 파일을 재사용합니다. S3-07 서버 계약을 변경하지 않습니다.

- 루트는 `/v1/user/session`으로 서버 세션 범위/만료를 확인한 뒤 대시보드를 엽니다. 보호 요청은 `X-Pct-Session`과 동일 origin 쿠키를 사용합니다. 현재값·과거값뿐 아니라 예측/실제값의 순차 조회도 이 경계를 통과합니다.
- 401 `USER_SESSION_EXPIRED`/`USER_UNAUTHENTICATED`는 세션을 끝내고 대시보드를 해제해 모든 메모리 값·커서·작업을 제거합니다. PC 변경으로 요청을 취소한 뒤 도착한 같은 세션의 401도 세션 종료 사유로 처리합니다.
- 현재값 404 또는 다른 조회의 `MACHINE_NOT_FOUND`, 403은 해당 PC 값·차트를 제거하고 작업을 해제합니다. 다른 PC 선택이나 명시적 지금 갱신으로 재확인할 수 있습니다. 권한 오류에 이전 값을 남기지 않습니다.
- 세션 확인(15초/가시성 변경)과 만료 처리는 인증용입니다. 수동 모드의 데이터 자동 조회/재시도가 아닙니다. 서버 세션을 확인하지 못하면 보호 화면을 닫고 사용자에게 다시 확인을 제공합니다.
- HTTPS 동일 origin의 S3-07 API와 로그인 어댑터 배포가 필요합니다. 이 브랜치에 S3-07의 서버 구현을 통째로 병합하지 않았습니다. 백엔드 API가 배포되지 않으면 세션 확인 오류가 표시됩니다.
