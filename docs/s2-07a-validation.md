## 적용

- 기존 DB에는 `database/migrations/003_quality.sql`을 한 번 적용한다. `sensor_quality_buckets`는 원본 관측 UTC 기준 10초·60초 단위의 센서 구성별 품질 건수다. `missing_count`는 수신한 명시적 결측을 센다. 순번 예약, 절전 또는 미도착 전송은 이 수치에 포함되지 않는다.
- 시각 API의 `CLOCK_PRECISION_FILE`에는 호스트 시계 모니터가 동기화를 확인한 동안 양의 정밀도(µs)를 원자적으로 발행해야 한다. API 프로세스가 읽을 수 있는 경로로 제공한다. 파일이 없거나 30초보다 오래됐거나 서버 시각이 역행하면 판정을 유보한다.
- 에이전트 `events.jsonl`의 `clock_measurement`에 왕복 입력, 오프셋, RTT, 불확실성과 판정을 남긴다. `buffer_transmission`의 체류 시간은 같은 부팅 세션의 절전 포함 단조 시각으로 계산한다. 이전 형식의 스풀이나 재부팅 전 배치는 체류 시간이 null이다.

## 남은 검증과 연동

- Windows .NET 10 SDK 환경에서 에이전트 빌드 후 실제 절전·재개, 역행, 네트워크 지연을 재현해야 한다. 위 합성 검증은 에이전트 실행 검증과 별개다.
- 시계 진단은 현재 에이전트 로컬 이벤트다. 서버에서 이상 구간을 PC 간 정렬·학습에서 제외하려면 진단 이벤트 전송 계약과 소비 경로를 담당자와 합의해야 한다. 운영 호스트 시계 모니터 배포 및 다른 팀원 리뷰도 남아 있다.
