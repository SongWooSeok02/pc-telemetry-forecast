# S3-06 실제값·예측값 비교 차트

작업 카드: [#38](https://github.com/SongWooSeok02/pc-telemetry-forecast/issues/38). #37 위에 쌓는 대시보드 후속 PR입니다. 실제 장비/서버 통합 검증 전이며 이슈를 완료로 변경하지 않습니다.

## 완료 기준과 화면

- 선택 PC의 CPU/GPU 온도 60초 후 예측과 보고된 원시 실제값을 같은 대상 시각 축에서 비교합니다. 온도 센서는 현재값 응답에서 CPU/GPU 식별자와 온도 단위(`C`, `Cel`, `°C`)를 확인해 목록으로 제시하고 사용자가 센서를 선택합니다. PC의 센서 매핑이 아직 없으면 미관측으로 안내합니다.
- 생성 시각, 대상 시각, 실제 모델 버전·상태·기준 모델 여부와 불가 사유를 툴팁/최근 20개 표에 표시합니다. 실선은 실제값, 파선은 학습 예측, 점선은 기준 예측입니다. 색 외에도 선 모양과 텍스트로 구분합니다.
- 미래 실제값은 대기, 지난 대상의 없는 실제값은 결측으로 표시합니다. 품질 오류·미지원·예측 불가는 0으로 대체하지 않습니다. 지원하지 않는 GPU는 조회를 등록하지 않습니다.
- 모델 버전/상태 전환, 예측 불가, 긴 공백(15초 초과)에서 예측 선을 끊습니다. 같은 대상 시각의 서로 다른 버전은 덮어쓰지 않습니다.
- 1시간/6시간을 지원합니다. PC·대상·센서·기간 변경 시 조회 캐시는 새 조건으로 분리하고 이전 응답을 현재 조건에 반영하지 않습니다. 차트 컴포넌트를 재생성하지 않아 상대 확대 범위와 브라우저 스크롤을 유지하며 페이지 새로고침을 하지 않습니다. 확대/축소는 네트워크 요청을 만들지 않습니다.

## 시각 매칭

예측은 `target_at - generated_at = 60초`를 만족해야 합니다. UTC 시각을 epoch 밀리초로 정규화하고 `대상 시각 ≤ 관측 시각 < 대상 시각 +1초` 안의 첫 원시 관측을 매칭합니다. 대상 시각보다 이른 관측이나 집계 평균은 정답으로 대체하지 않습니다. 대상/실제 관측이 조회 기준 시각보다 미래이면 아직 표시하지 않습니다.

실제 선은 매칭된 관측값을 예측의 대상 시각 축에 배치합니다. 실제 관측 UTC 및 수신 시각은 툴팁에 따로 표시합니다. 1초 매칭 허용 구간은 S3-05의 소수 초 대상 시각과 1초 센서 수집을 연결하는 프런트엔드 제안이며 담당자 검토가 필요합니다. 이 범위를 벗어난 값은 근사 보간하지 않습니다.

## 조회 계약과 증분

공통 `QueryScheduler`에 `forecast-comparison` 작업 하나를 등록합니다. 현재값·과거 차트와 동일한 진행 슬롯에서 예측과 실제값 HTTP 조회를 순서대로 실행합니다. 별도 자동 타이머·실패 재시도는 추가하지 않습니다. 수동 모드에서도 최초 선택과 지금 갱신만 요청하고, 숨김 시 취소하며 복귀 자동 요청은 없습니다.

1. S3-05의 `GET /v1/machines/{machine_id}/predictions?sensor_id=…&start=…&end=…&limit=5000`를 사용합니다. 범위는 대상 시각 기준이며 현재부터 +60초의 미래 예측까지 포함합니다. 첫 조회 이후에는 직전 조회 종료의 120초 전부터만 겹쳐 조회합니다. S3-05가 과거 슬롯을 다시 채우지 않는 append-only 계약을 전제로 합니다.
2. `items`/`truncated` 페이지 형식을 따릅니다. 잘린 경우 시간 범위를 반으로 나눠 순차 조회하고 최대 32회/동일 1ms 밀집 한도를 적용합니다. 마지막 대상 시각 다음으로 건너뛰어 같은 시각의 다른 버전을 잃지 않습니다.
3. 원시 실제값은 S2-05의 `GET /v1/dashboard/machines/{machine_id}/sensors/{sensor_id}/history?from=…&to=…&resolution=raw`로 시작한 뒤 `nextCursor`만 전달합니다. 늦게 도착한 실제값은 관측 시각 키로 갱신하고 이미 표시한 예측과 다시 매칭합니다. 원시 응답의 동일 관측 시각에 서로 다른 값/품질이 있으면 모호한 응답으로 거부합니다.
4. 예측은 `(target_at, generated_at, model_version)` 키로 병합합니다. 기간 밖은 제거하고 모델/PC/센서/단위/기간을 섞지 않습니다. 두 조회 모두 성공하고 요청/컴포넌트가 유효한 경우에만 캐시를 교체합니다. 중간 서버 오류에는 같은 조건의 이전 결과를 유지하고 오류를 표시합니다.
5. `credentials:include`를 사용합니다. API 세션과 PC 소유권 검증은 서버 책임이며 브라우저에서 우회하지 않습니다. 다른 origin을 사용할 때는 서버의 credential/CORS 배포 구성이 필요합니다.

예측 항목의 프런트엔드 계약:

```text
target_at, generated_at: UTC ISO-8601
unit: 예측 당시의 단위, 현재 선택 센서와 정확히 일치
value: 유한 수치 또는 null
model_version: 실제 사용한 버전
status: ok | fallback | unavailable
reason: 문자열 또는 null
```

`unavailable`은 null, `ok/fallback`은 유한 수치여야 합니다. `fallback` 또는 `builtin:` 버전은 기준 모델로 표시합니다. 단위 누락/불일치, 60초가 아닌 지평, 잘못된 모델/수치, 잘못된 PC·센서 실제값 응답은 반영하지 않습니다. `Cel`과 `°C`를 추정 변환해 조용히 연결하지 않습니다.

### S3-05 연동 계약 및 구 레코드 처리

S3-05 후속 서버 패치(`database/migrations/006_prediction_unit.sql`, `backend/forecast.py`, `backend/history.py`)는 예측 생성 시점의 `forecast_targets.unit`을 `predictions.unit`에 저장하고 `GET /v1/machines/{machine_id}/predictions` 응답에 포함합니다. `006_prediction_unit.sql`은 `unit`을 nullable로 추가하며 구 레코드에 현재 대상 단위를 백필하지 않습니다. 이 화면은 구조가 정상인 `unit: null` 구 레코드를 현재 센서 단위로 추정하거나 차트에 그리지 않고 제외하며, 같은 페이지의 유효한 예측 행은 정상 렌더링합니다(제외된 구 레코드 구간의 15초 초과 공백은 선을 끊어 유지). 반면 `unit` 누락(`undefined`), 빈 문자열, 불일치 단위, 잘못된 지평·수치 등 형식 오류 레코드는 계속 엄격히 거부합니다. `dashboard/tests/forecastHttpIntegration.test.ts`에서 S3-05/S2-05 계약 픽스처 기반 로컬 HTTP 응답(정상, 혼합, 구 레코드 단독)이 `readForecastUpdate`와 `ForecastChart` 렌더링을 통과하는지 검증합니다(실제 FastAPI/PostgreSQL 서버 검증은 별도 백엔드 통합 환경에서 수행).

`조회 기준`은 요청 시작 시각이고, 실제 수신 시각과 `aggregationUpdatedAt`/`aggregationPending`은 별도로 표시합니다. 이 차트는 집계 평균과 순간 예측의 혼동을 피하려고 원시 실제값만 매칭합니다. 긴 기간 집계 비교와 실제 서버 지연 재집계 검증은 별도 작업입니다. 커서 만료/조회 오류는 UI에 표시하며 사용자는 조건을 다시 선택해 초기화할 수 있습니다.
