# S2-05 과거 조회 화면 및 API 연결 계약

## 화면 동작

- 조회 PC, 센서, 기간(1시간·6시간·24시간·7일·30일·90일)을 명시적으로 선택합니다. PC를 바꿔도 선택 기간과 차트 확대 범위를 유지하고, 응답이 바뀌는 동안 이전 PC의 데이터는 현재 선택 데이터로 표시하지 않습니다.
- 6시간 이하는 원시, 24시간 이하는 10초 집계, 7일 이하는 1분 집계, 30일 이하는 5분 조회 집계, 90일은 1시간 조회 집계를 요청합니다. 5분·1시간 단위는 보존된 1분 집계를 조회 시 롤업해 전송량을 제한합니다. 선택 기간에 맞춰 `from`/`to`를 제한하며 전체 보존 데이터를 내려받지 않습니다.
- 첫 요청의 `nextCursor`를 보관해 다음 자동 갱신부터 커서만 보내 증분 조회합니다. 같은 버킷의 재집계 결과는 `bucketStart` 기준으로 교체하고, 기간 밖의 데이터는 화면 캐시에서 제거합니다.
- 평균값은 실제 값과 구분해 표시하고, 표본 수·마지막 관측 시각·마지막 수신 시각·집계 갱신 시각을 툴팁과 상태 영역에서 확인할 수 있습니다. 시각은 브라우저 현지 시간으로 표시합니다.
- 값이 null이거나 품질 상태가 `missing`, `unsupported`, `error`인 구간은 0으로 바꾸지 않습니다. 해당 점에서 선을 끊고, 해상도 기준으로 긴 공백도 선으로 잇지 않습니다.
- 숫자 확대/축소와 전체 범위 복귀는 화면 상태만 바꾸며 기간 재조회는 발생시키지 않습니다. 네트워크 오류 때는 직전 정상 응답을 유지하면서 오류를 표시합니다.

## 제안된 읽기 API

현재 백엔드에는 이 읽기 API와 사용자별 접근 제어가 없습니다. 따라서 다음은 프런트엔드 연결 계약이며, 인증/소유권 검증을 갖춘 서버 구현 및 S3-03 집계 배포 전까지 화면은 오류 상태를 표시합니다. 현재 저장소의 수집 API를 읽기 경로로 우회하거나 가짜 차트 데이터를 만들지 않습니다.

`GET /v1/dashboard/machines/{machine_id}/sensors/{sensor_id}/history`

| 쿼리 | 설명 |
|---|---|
| `from`, `to` | RFC 3339 UTC 경계. 반개구간 `[from, to)` |
| `resolution` | `raw`, `10s`, `1m`, `5m`, `1h` |
| `cursor` | 초기 조회 조건(PC·센서·해상도·`from`)에 묶인 불투명 증분 커서. 생략 시 초기 조회 |

성공 응답 예시:

```json
{
  "machineId": "registered-machine-id",
  "sensorId": "cpu_temperature",
  "unit": "°C",
  "resolution": "10s",
  "points": [
    {
      "bucketStart": "2026-11-05T00:00:00Z",
      "bucketEnd": "2026-11-05T00:00:10Z",
      "lastObservedAt": "2026-11-05T00:00:09Z",
      "receivedAt": "2026-11-05T00:00:12Z",
      "value": 52.5,
      "max": 54.1,
      "sampleCount": 10,
      "quality": "ok",
      "aggregationUpdatedAt": "2026-11-05T00:00:14Z"
    }
  ],
  "nextCursor": "opaque-server-cursor",
  "aggregationUpdatedAt": "2026-11-05T00:00:14Z",
  "aggregationPending": false
}
```

`points`는 관측 버킷 시작 순으로 반환합니다. 평균을 `value`에 담고 최대값과 유효 표본 수를 별도 반환합니다. 유효 표본이 없거나 센서가 미지원인 버킷은 `value`/`max`를 null로 두고 `quality`를 전달합니다. 누락 버킷을 합성하지 않으며, 클라이언트는 긴 시간 간격도 선으로 연결하지 않습니다. 지연 데이터가 도착해 기존 버킷이 바뀌면 증분 응답에 그 버킷을 다시 포함해 클라이언트가 교체할 수 있도록 합니다. `nextCursor`는 매 응답에서 필수이며 이후 요청은 커서만 보냅니다. 서버는 첫 조회 이후 새 데이터 및 재집계된 버킷을 스트리밍하고, 클라이언트가 오래된 버킷을 기간 캐시에서 제거합니다. 기간·PC·센서 변경 시 새 초기 조회를 시작해야 합니다.

## 미완료 검증 및 의존성

- 읽기 API 및 사용자·PC 소유권 검증은 미구현입니다. S2-04의 목록/접근 계약 및 S3-03 집계 작업과 합의한 뒤 서버에 연결해야 합니다.
- 실제 PC·센서의 집계 자료, 지연 재집계, 시간대 전환, 서버 접근 제어 통합 검증은 완료하지 않았습니다.
- 현재 브라우저 코드의 증분 커서·차트 동작은 연결 계약 구현 기준입니다. API가 연결되기 전 자동 갱신은 서버 응답 오류를 표시합니다.
