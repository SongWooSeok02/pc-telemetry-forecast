# S2-07b 기준 모델 평가

후속 온도 모델 학습·채택 판단·기준 모델 반환 도구는 [S3-04 온도 모델](TEMPERATURE_MODEL.md)에 설명합니다.

표준 라이브러리만 사용하는 재현 가능한 기준 모델 평가기입니다. 현재값 유지(persistence)와 최근 300개 유효 1초 값의 이동 평균을 비교하고, 검증 구간 MAE가 더 낮은 기준 모델을 PC·센서별로 선택합니다. 최종 테스트 점수는 선택에 사용하지 않습니다.

## 입력 CSV

UTF-8 CSV이며 헤더는 다음 열을 포함해야 합니다.

```csv
machine_id,sensor_id,observed_at,value,quality,workload
pc-a,cpu/package/temp,2026-11-01T00:00:00Z,52.5,ok,idle
```

- `observed_at`은 UTC ISO-8601 정각 초여야 합니다. 입력은 장비·센서별 초당 시계열로 정렬할 필요는 없지만 같은 장비·센서·초 중복은 거부합니다.
- 1초마다 없는 샘플, `quality != ok`, null/비유한 값은 결측으로 취급합니다. 보간이나 0 대체를 하지 않으며 입력 300초 중 하나라도 결측이면 해당 예측 예제를 제외합니다.
- `workload`는 `idle`, `high_load`, `transition` 중 하나입니다. 그 외 값은 `unlabeled`로 보고 전체 집계에만 포함합니다. 원천 라벨과 이 정규화 매핑은 S1-09/S2-07a 계약에 맞춰 수출 단계에서 확정해야 합니다.

## 실행

```powershell
python -m ml.evaluate_baselines telemetry.csv --machine-id pc-a --sensor-id cpu/package/temp --output reports/pc-a-cpu-temp.json
```

기본 분할은 최신 관측 시각에 1초를 더한 배타 종료 시각에서 역산하여 train 5일, validation 1일, test 정확히 48시간입니다. 테스트 시작은 배타 종료에서 48시간을 뺀 시각이므로 최신 관측을 포함하면서도 테스트가 1초 늘어나지 않습니다. 필요한 경우 `--train-days`, `--validation-days`, `--test-days`로 기간을 지정합니다. 각 split 안에서 300초 입력 전체와 +60초 정답이 경계를 넘는 예제는 생성하지 않습니다. 각 장비·센서의 split 유효 예제 부족은 결과 상태에 남습니다.

각 실행은 PC와 대상 센서 하나를 처리해 원시 시계열 메모리 사용량을 제한합니다. 입력 SHA-256은 전체 파일을 대상으로 하며 대상 행만 평가합니다. 대상별 출력을 반복 실행해 결과를 보관합니다. JSON 보고서에는 파이프라인 버전, 입력 SHA-256, 실행 UTC, 분할 경계와 설정, 품질 결측률, 모델별 전체/부하 상태 MAE, 표본 수, 검증에서 고른 기준, 최종 테스트에서의 다른 기준 대비 개선율을 보관합니다. 보고서 경로는 호출자가 선택하며 원시 입력을 저장소에 추가하지 않습니다.

## 현재 제한

S2-07a의 품질 집계 구현과 S1-09 실제 부하 라벨·수집 CSV가 아직 이 저장소에 없습니다. 따라서 실제 PC별 기준 MAE와 결측률은 산출하지 않았습니다. 시험 데이터의 보고서를 실제 장비의 성능 증거로 사용하지 말고, 계약 연동 후 실제 라벨 데이터로 다시 실행해야 합니다. 이 도구는 아직 학습 회귀 모델이나 예측 배포를 구현하지 않습니다.

## 2차 리뷰 및 자체 코드 리뷰 기록 (2026-11-19 KST)

- 완료 기준: 현재값 유지·이동 평균과 시간순 평가, 입력 300초·예측 60초 경계 누출 방지, 학습 데이터에만 맞춘 전처리, 유휴·고부하·전환 MAE·결측률·기준 대비 개선율 기록. 현재 기준선은 스케일러 등 학습 가능한 전처리를 사용하지 않으며 검증 MAE만으로 선택합니다.
- 테스트 종료를 latest + 1초로 먼저 정하고 그 종료에서 test_days를 뺍니다. train/validation도 동일 경계에서 역산해 분할이 겹치거나 비지 않게 합니다. 소수 초 앵커 올림과 배타 종료 전 정답 규칙은 유지합니다.
- 재현 가능한 결과 식별을 위해 파이프라인 버전을 s2-07b.2로 올렸습니다. 이전 버전과 경계가 달라 결과를 그대로 섞어 비교하지 않습니다.
- 3차 리뷰(2026-11-28): `invalid_quality_rows`는 사용할 수 없는 행(quality가 ok가 아님, 빈 값, 숫자 아님, 비유한 값)을 행당 정확히 한 번 셉니다. 이전에는 quality=ok이면서 값이 빈 행을 두 번 셌습니다. 보고서 수치가 달라지므로 파이프라인 버전을 s2-07b.3으로 올렸고, 빈 값·NaN·inf·문자열·비정상 quality·혼합 행 회귀 검사 2개를 추가해 unittest 10개가 통과합니다.
- (2차 리뷰 당시 기록) Windows x64 / 번들 Python 3.12 / 합성 고정 데이터: unittest 8개 통과. 현재 `s2-07b.3`의 검사 수는 위 3차 리뷰 항목의 10개입니다. 기본 5일·1일·48시간의 정확한 길이와 연속 경계, 최신 정답 포함, 600초 구간의 후보 241개, 소수 경계·결측·검증 선택 검사 통과. compileall 및 git diff --check도 수행합니다.
- 자체 코드 리뷰: 오늘의 분할 수정, 기존 정수 초 앵커·배타 종료, 선택용 검증/평가용 테스트 분리와 학습 전처리 사용 여부를 검토했습니다. 실제 PC 데이터 평가는 수행하지 않았으며 실측 MAE·결측률 및 채택 판단은 미완료입니다.
