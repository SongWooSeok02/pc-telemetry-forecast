# S3-04 온도 모델 학습·시간순 평가

작업 카드: [#36](https://github.com/SongWooSeok02/pc-telemetry-forecast/issues/36). 사용자가 전달한 온도 모델 작업의 저장소 ID는 S3-04입니다. S2-07b(#21) 기준 모델 위에 쌓는 후속 구현입니다.

**현재 상태: 오프라인 학습/평가·기준 모델 반환·재추론 도구 구현. 실제 PC 데이터 미제공으로 실측 평가는 미완료.** 실제 센서 지원, 5일/1일/48시간 데이터 확보, 대상별 유효 전환 10회 확보나 모델 채택을 이 PR로 완료 처리하지 않습니다. 합성 데이터는 단위 검사에서만 만들며 실측 증거로 사용하지 않습니다.

## 입력과 품질 계약

PC와 CPU/GPU 대상 하나씩 실행합니다. 기존 telemetry 계약이나 S1-09 라벨을 변경하지 않고 별도 분석용 CSV를 사용합니다. S1-09/S2-07a 담당자와 최종 수출 매핑 합의가 필요합니다.

필수 CSV 열:

```text
machine_id,target,observed_at,temperature,temperature_quality,time_quality,workload,boot_session_id,sensor_config_id
```

- `target`: `cpu` 또는 `gpu`. 온도 단위는 °C(`Cel`)입니다.
- `observed_at`: UTC 정수 초. 장비·대상별 같은 초의 중복 행은 오류입니다. 입력 파일 전체 SHA-256을 기록합니다.
- `temperature_quality`: `ok`인 유한 수치만 사용합니다. 오류·미지원·결측·빈 값·NaN·Infinity는 유효 수치로 바꾸지 않습니다.
- `time_quality`: 상류의 시계/시간 품질 결과를 `ok` 또는 그 외로 수출합니다. `ok`가 아니면 해당 행의 모든 특징을 제외합니다. 시각을 임의 보정하지 않습니다.
- `workload`: `idle`, `high_load`, `transition`. 그 외는 `unlabeled`로 전체 점수에만 포함하고 세 상태의 하위 집계에서 제외합니다. 이 필드는 오프라인 평가 라벨이며 미래 부하 라벨을 입력 특징으로 사용하지 않습니다.
- `boot_session_id`와 `sensor_config_id`를 기록합니다. 5분 창에서 값이 달라지거나 정답이 다른 부팅/센서 구성에 속하면 해당 예제를 제외합니다.

선택 열은 `power`(W), `utilization`(%), `clock`(MHz), `fan`(rpm) 및 각 `<열>_quality`입니다. 해당 품질 열이 없거나 `ok`가 아니면 미관측으로 취급합니다. 선택 특징은 **학습 구간만** 보고 90% 이상 유효 관측이 있는 신호를 고릅니다. 검증/테스트 센서 가용성이 선택에 영향을 주지 않습니다. 선택되지 않은 신호는 0으로 넣지 않고 특징에서 제거합니다. 운영 시 같은 센서 구성·단위로 수출해야 합니다.

라벨 JSON은 S1-09 sidecar 세션 한 개 또는 세션 배열입니다. `machine_id`, `session_id`, `boot_session_id`, `sensor_config_id`, `transitions`를 읽으며 나머지 원천 필드는 보존합니다. 입력 라벨 파일 SHA-256 및 실제 라벨 관측 기간, 평가에 사용한 테스트 기간을 별도로 기록합니다. 원시 telemetry/라벨과 모델 결과는 접근 제한된 위치에 보관하고 저장소에 실측 원본을 올리지 않습니다.

## 학습과 경계

기본 분할은 최신 관측 +1초를 배타 종료로 삼아 역산한 학습 5일·검증 1일·최종 테스트 48시간입니다. CLI로 늘릴 수 있으며 최소 기간 미만·비유한 기간은 거부합니다. 실제 관측 시작/종료가 각 구간을 덮는지, 온도 유효 초 비율과 예제 유효 비율이 각각 90% 이상인지 검사합니다. 90%는 이 구현의 명시적 품질 정책이며 채택 기준을 완화하는 CLI 옵션은 없습니다.

60초 간격의 고정 UTC 격자에서 입력 300개 정수 초와 +60초 정답을 구성합니다. 입력 전체와 정답은 같은 분할에 있어야 합니다. 필요한 1초 값이 하나라도 없거나 품질이 나쁘면 제외하고 보간하지 않습니다. 절전·재부팅·긴 공백을 연결하지 않습니다. 평가용 60초 간격 표본을 독립 전환 횟수로 세지 않습니다.

온도 특징은 최신값·5분 평균·초당 양 끝 기울기·최솟값·최댓값입니다. 유효한 전력/부하/클럭/팬은 최신값·평균·기울기를 추가합니다. 표준화 평균·표준편차와 ridge 계수는 학습 예제에서만 맞춥니다. 상수 특징 표준편차는 1로 처리합니다. ridge `alpha=1.0`은 고정 기본값이고 난수나 탐색을 사용하지 않습니다. 테스트 보고서를 보고 alpha/특징/품질 기준을 재선택하지 말고 새 최종 홀드아웃을 확보해야 합니다.

현재값 유지와 직전 5분 평균을 동일한 유효 예제에서 비교합니다. 검증 MAE만으로 더 좋은 기준 모델을 고르며 동점은 현재값 유지입니다. 검증 데이터가 없으면 현재값 유지를 제공합니다. JSON 보고서에 두 기준과 학습 모델의 구간별 점수·결측률·표본 수를 모두 남깁니다. 대상 관측 자체가 없으면 임의 데이터 기간을 만들지 않고 `no_observations`와 기준 모델 산출물을 남깁니다.

## 채택과 기준 모델 반환

아래 조건을 모두 충족해야 `selected_model=ridge`가 됩니다.

1. PC·대상별 최소 관측 기간, 학습/검증/테스트 품질 비율과 학습 가능 예제 수를 충족합니다.
2. 최종 테스트 안에 라벨 검토 완료(`validation=valid`, `transition_status=observed`)된 대상 전환이 10회 이상 있습니다. 해당 경계 주변의 5분 입력과 +60초 정답도 품질·동일 부팅/구성을 충족해야 합니다.
3. 검증에서 고른 더 좋은 기준 대비 테스트 전체 MAE가 10% 이상 개선됩니다.
4. 고부하·전환 각각의 테스트 MAE가 같은 기준 대비 5%를 초과해 악화되지 않습니다. 해당 상태의 점수가 없으면 채택하지 않습니다. 하위 기준 MAE가 0이면 모델 MAE도 0이어야 합니다.
5. 전체 기준 MAE가 0.1°C 미만이면 상대 개선율로 채택하지 않고 기준 모델을 유지합니다. 0.1°C는 포함 경계입니다. 공통 판정 함수는 W 대상의 1W 경계도 검사하지만 **이 파이프라인은 온도 전용**입니다.

CPU의 유휴→CPU/CPU→냉각, GPU의 냉각→GPU/GPU→냉각만 대상별 전환으로 인정합니다. 같은 세션·경계, 전환 ID, 정수 초로 정렬된 중복 시각을 여러 번 세지 않습니다. 다른 시각에 재사용된 ID는 오류입니다. CPU/GPU별 세션당 2회이므로 제외가 없을 때 최소 5세션이 필요합니다. 품질 제외나 중단이 있으면 추가 수집합니다.

데이터·전환·점수·성능이 부족하면 선택 기준 모델과 미채택 사유를 제공합니다. 학습 모델의 특징이 추론 시 빠지면 기준 모델로 대체합니다. 이동 평균도 300초 유효 입력을 확보하지 못하면 현재값 유지로 내려갑니다. 최신 온도가 결측이면 과거값을 최신값처럼 내놓지 않고 `unavailable`을 반환합니다. `served_model`과 `fallback`으로 실제 제공 모델을 표시합니다.

## 실행과 전달

```powershell
python -m ml.temperature_model train --input telemetry.csv --labels sessions.json --machine-id PC_ID --target cpu --output-dir local-evidence/cpu-model
python -m ml.temperature_model predict --input latest-5min.csv --artifact local-evidence/cpu-model/model.json
```

GPU는 `--target gpu`로 별도 실행합니다. `--labels`가 없으면 전환 수 0으로 판단하여 기준 모델을 제공합니다. `--train-days`, `--validation-days`, `--test-days`는 각각 5/1/2 이상, `--alpha`는 유한한 양수만 받습니다.

- `model.json`: `s3-04.1` 버전, PC/대상/단위, 특징 순서, 학습 표준화·회귀 계수, 선택 모델·기준 모델, 입력/라벨 해시. pickle 실행이나 외부 ML 패키지가 필요 없습니다.
- `evaluation.json`: 설정, 환경/실행 UTC, 데이터·라벨 기간과 분할 경계, 품질 제외에 따른 결측률, 두 기준/모델의 전체·유휴·고부하·전환 MAE와 표본 수, 독립 전환 수, 상대 개선율과 채택 사유.
- `comparison.md`: 사람이 읽을 수 있는 기준 대비 비교표. `미산출`은 0점이 아닙니다.

S3-05는 JSON과 `infer()`를 같은 버전으로 사용해야 하며 배포 서비스 연결은 별도 작업입니다. S4-05에는 실측 CSV/라벨 해시, 위 보고서, 부하/전환 수 증거를 함께 전달해야 합니다. 이 PR은 서비스 배포나 실측 채택 결정을 포함하지 않습니다.

Windows x64 / 번들 Python 3.12 / 2026-11-19 KST / 파이프라인 `s3-04.1`에서 고정 합성 데이터로 검사합니다.

검사는 분할 누출·미래 데이터에 영향받지 않는 표준화/특징 선택·품질 결측·재부팅 경계·10%/5%/.1°C/1W 경계·전환 중복·빈 데이터·산출물 재추론을 포함합니다. 8일 전체 길이의 합성 통합 검사는 5일/1일/48시간, 대상별 전환 10회와 낮은 기준 MAE 시 기준 모델 유지를 확인합니다. CLI도 임시 합성 CSV로 학습→파일 저장→재추론을 확인합니다. 합성 데이터는 실측 온도 또는 성능 결과가 아닙니다.

최종 결과는 온도 모델 16개와 기존 기준 모델 8개, 총 24개 통과입니다. 컴파일과 공백 검사도 통과했습니다. 실제 실행 UTC·OS/빌드·기대값/실제값·재현 명령은 [검증 기록](../docs/s3-04-validation.json)에 남깁니다. Ubuntu/Windows CI에 같은 검사를 연결했으며 원격 실행 결과는 별도로 확인합니다.

자체 코드 리뷰에서 빈 대상 입력에 임의 시각을 보고하지 않도록 수정하고, 같은 경계/시각의 중복 전환을 제거하며 실제 라벨 기간과 테스트 기간을 구분했습니다. 최종 테스트를 설정 선택에 사용하지 않는지와 학습 전처리만 직렬화하는지도 검토했습니다.

**현장 차단:** 실제 PC CSV·지원 센서·확정 품질/라벨 수출 매핑과 수집 기간 증거가 없습니다. S1-09·S2-07a 담당자가 데이터/매핑을 제공하고 C가 다음 평가를 실행해야 합니다. 다음 확인은 입력 자료 제공 시점이며, 실측 지표·대상별 10회 확인·실제 추론 통합·팀원 1명 리뷰 및 CI 통과 전에는 완료로 변경하지 않습니다.
